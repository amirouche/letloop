# 0x0009 — Two archives defining one symbol must fail the link

**Status:** open
**Severity:** high, a wrong function can be linked with no diagnostic
**Area:** `letloop compile`

## Problem

Archives are linked inside `-Wl,--start-group`, so the linker resolves
order itself, and by the same token resolves a symbol defined twice by
whichever archive it scans first. Nobody chose that. libsodium and
libargon2 both define `argon2id_hash_raw` and sixteen more; a program
importing both bindings links one of the two implementations silently.
Decision 8 in `0x0000`: this is an error.

## Fix

`archive-symbols` already reads every defined global symbol of every
archive via `nm`. Before linking, collect them per archive and refuse
if a symbol appears in two, naming the symbol and both archives, exit
nonzero. Resolution is by choosing packages, never by link order: the
known case is settled by `(letloop argon2)` declaring the `sodium`
package (`0x0007`), since libsodium vendors argon2. `nm` comes from the
store's toolchain (`0x0006`), not the host.

## Gate

`checks/compile-conflict.sh`: a program importing two bindings whose
packages both define one symbol fails to compile with the symbol named.
