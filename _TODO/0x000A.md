# 0x000A — Store paths carry the system; fetches carry a list of URLs

**Status:** open
**Severity:** low now, high once outputs exist that would have to move
**Area:** `(letloop store)`

## Problem

Two data-shape changes that cost nothing today and a migration later.

**System.** Store paths are `<store>/<name>-<hash>`. The store is
x86_64-linux-musl only, and will stay so for a while, but a second
system added later would have to move every existing output. Decision
9 in `0x0000`: paths become `<store>/<system>/<name>-<hash>` now, fetch-only
outputs included, since a toolchain tarball is as system-specific as
anything built with it.

**Mirrors.** A fetch has one `(url ...)`. The toolchain comes from
musl.cc, a one-person site that has been offline before. Decision 2:
`url` takes one or more strings, tried in order, every byte hash-checked
regardless of which answered. letloop.cloud is added to the list when
it exists; until then upstream is the only entry and nothing depends on
the mirror.

## Gate

Existing store checks pass with the new layout; a fetch whose first
URL is unreachable succeeds from its second (`~check-store-*/fetch-mirrors`).
