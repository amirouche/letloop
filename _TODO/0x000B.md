# 0x000B — Ship a static `bwrap`; write the release gate

**Status:** open
**Severity:** medium, the last two host dependencies the claim does not allow
**Area:** bootstrap chain, `checks/`

## Problem

`letloop store build` runs every build under the host's `bwrap`. A
release that needs a host package to build a user's C library does not
meet the claim in `0x0000`. Decision 3: the chain builds `bwrap`
statically and installs it beside the binary; `sandbox-build!` runs
that one. Unprivileged user namespaces stay a host requirement, and
their absence is reported in one sentence naming the sysctl before
anything is attempted.

Separately, nothing today exercises a release as a user meets it.
`bootstrap.scm` gates the chain from the machine that ran it, which has
a compiler, `bwrap` and a letloop checkout.

## Fix

1. A `bwrap` package from source, static, in the chain; installed to
   `$PREFIX/bin/bwrap`; found by walking up from `/proc/self/exe`.
2. `checks/release.sh`: unpack the release tarball into a container
   with no `cc`, no `bwrap`, no headers and no `LETLOOP_*` variable, and
   run the acceptance test from `0x0000` there. Assert no `INTERP`
   segment on the result and that it runs from an empty directory. This
   is the one gate for the whole claim, and runs locally: no hosting is
   involved.

## Gate

`checks/release.sh` itself, plus `bootstrap.scm`'s self-hosting gate
run with `bwrap` masked from `$PATH`.
