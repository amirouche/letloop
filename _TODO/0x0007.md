# 0x0007 — A binding library names its package explicitly

**Status:** open
**Severity:** medium, replaces silent inference with a diagnosable declaration
**Area:** `(letloop cffi)`, `letloop compile`

## Problem

`letloop compile` infers a package from a binding library's name,
longest suffix first, and consults only libraries that call
`define-shared-object`. When the convention is not followed nothing is
linked and nothing is said until run time. The consult-only-declarers
rule exists to keep fixture packages from being built by a name match,
a workaround for the inference itself. Decision 4 in `0x0000`: the
binding declares its package.

## Shape

`define-shared-object` gains a package clause:

```scheme
(define-shared-object libarith (package arith) "libarith.so")
```

`(package NAME)` resolves as `store build` does: `(package NAME)` first,
`(letloop package NAME)` second. A binding with no clause links nothing
and compile says so in one line. A clause naming a package that
resolves to no library is a compile error. `library-package-components`
and the longest-first walk go away. Every shipped binding under
`src/letloop/` gains a clause; `(letloop argon2)` names `sodium`, which
vendors argon2 (see `0x0009`).

## Gate

A binding with a bad package name fails to compile with the name in
the message. `checks/compile-unbuilt.sh` covers the built-but-missing
half; this one is the not-declared half.
