# 0x0008 — Compile resolves a package by derivation key, through a store index

**Status:** open
**Severity:** high, it is the fix under `0x0002` and half of `0x0004`
**Area:** `letloop compile`, `(letloop store)`

## Problem

Compile finds an archive by scanning the store for `<name>-*`, and
declines to choose when two paths match. So a package rebuilt after an
edit reports as unbuilt, and the program falls back to dlopen. The
build already writes `.cache/<key> -> <path>`, where the key hashes the
derivation, its rootfs and its resolved inputs; it is documented as a
cache, not a source of truth. Decisions 5 and 6 in `0x0000` make that
mapping the store's index and have compile use it.

## What changes

1. Rename `.cache` to `index`, and treat an entry as authoritative: an
   entry whose target is missing is a corrupt store, reported, not
   silently skipped.
2. A resolver that computes a derivation's key without building it,
   walking `(package ...)` and `(derivation ...)` inputs through the
   index. Any miss along the walk means "not built", reported with the
   package name and `letloop store build NAME`.
3. `letloop compile` uses the resolver; the name scan goes away. A miss
   exits nonzero (`0x0002`).
4. `store build` writes the index entry it already writes, under the
   new name, and `store gc` (`0x0004`) treats entries as roots.

## Cost, accepted

Compile loads each declared package library to read its `package`
export, so the package directory must be on compile's path (`0x0003`).
Inputs that are store paths cost a string compare each; a package whose
input is a bind-mounted host directory is hashed, which is what the
cache already does.

## Gate

`~check-store-*/index-lookup`: build a package, edit its derivation,
rebuild, and compile resolves the new output; remove the index entry
and compile reports it unbuilt.
