# 0x0003 — The installed package directory is visible to `store build` and not to `compile`

**Status:** open
**Severity:** medium, a confusing asymmetry rather than a crash
**Area:** `letloop store`, `letloop compile`

## Problem

A project's own packages are meant to live at
`$LETLOOP_PREFIX/lib/letloop/package/NAME.scm`, which is the directory
`project-library-directory` returns. `letloop store build` puts that
directory on the library path before resolving a package name, so a user
who installs a package there can build it by bare name:

```
letloop store build arith
```

`letloop compile` does not. It sets the library path from the directories
named on its own command line, so when `infer-archives!` asks the store
for `(package arith)`, that library is not found and the package resolves
to nothing. The archive is not linked and the program falls back to
dlopen, per `0x0002`.

The result is that the installed location works for half of the workflow.
A user can build a package by name and then not link it, and the fix is to
repeat a path they thought they had installed away.

## Evidence

`project-library-directory` is defined at `src/letloop/store.body.scm:569`
and referenced exactly once, at line 594, inside `letloop-store`'s own
argument handling. No call site exists in `letloop-compile`.

The user story verified on this branch worked only because the package
directory was passed explicitly:

```
letloop compile /tmp/user-project app.scm main
```

with `package/arith.scm` sitting inside `/tmp/user-project`.

## Why it matters

It is the difference between a package being installed and a package being
a path someone has to remember. It also undercuts the in-prefix store
decision: the prefix is supposed to be the place where a letloop
installation keeps its things, and packages are one of those things.

## Fix

Have `letloop compile` add `project-library-directory` to the library path
the same way `letloop store build` does, after the command line
directories so an explicit path still wins.

Two details to get right. The addition has to happen before
`infer-archives!` runs, and it must not disturb the amalgamating compile's
rule that no letloop library be instantiated in the compiling process,
since a package library is instantiated to read its `package` export.

Worth checking at the same time whether `letloop check` needs it, since it
compiles the checks it runs and therefore takes the same inference path.
